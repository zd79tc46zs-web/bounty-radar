### 为什么 git push 也失败

现象是 `remote: Invalid username or token. Password authentication is not supported for Git operations.`

这**不是 token 无效**——同一个 token 调 REST API 完全正常（已成功上传 18 个文件、建仓成功）。
原因是 git over HTTPS 走的是 OAuth token 认证路径，对细粒度 token 的支持与 REST API 不同，
且需要 `workflow` scope 的经典 token 才行。

**结论：git push 这条路在你的网络+token 组合下走不通，别再折腾了。**
我已经用 `upload_via_api.py` 通过 REST API 实现了等价效果，效果完全一样。

## 三、两个额外的网络问题（已定位，非权限问题）

### 1. HTTP/2 framing 错误

第一次 `git push` 报：
```
fatal: unable to access '...': Error in the HTTP2 framing layer
```
加上这两行就解决了（已写进项目的 git config）：
```bash
git config http.version HTTP/1.1
git config http.postBuffer 524288000
```

### 2. 代理端口 502

`git push` 报 `CONNECT tunnel failed, response 502`。
原因：**你的终端环境里没有代理环境变量**。WorkBuddy 进程内部有代理（端口 51536），
但那是注入到 WorkBuddy 自己的进程环境里的，你手动开的终端拿不到。

检测方法（在你的终端里跑）：
```bash
env | grep -i proxy
```
**如果什么都没输出，说明你的终端没有代理配置**，这就是 git 推送失败的根本原因。
