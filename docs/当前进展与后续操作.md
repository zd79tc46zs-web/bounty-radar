## 五、技术要点（实测踩坑记录，供后续维护参考）

### Actions 密钥配置的正确做法

GitHub 的 `public-key` 接口返回的是 **libsodium 公钥**（32 字节裸 base64），
官方要求用 `crypto_box_seal` 加密，**不是 RSA/OAEP**。
参考：<https://docs.github.com/en/rest/guides/encrypting-secrets-for-the-rest-api>

macOS 自带 LibreSSL 3.3 **不支持 X25519**，无法用 openssl 完成加密
（`openssl pkeyutl -pubin` 会报 "unable to load Public Key"）。
最终方案：用 Node 的 `libsodium-wrappers`：

```bash
npm install libsodium-wrappers
node -e "
const sodium=require('libsodium-wrappers');const fs=require('fs');
sodium.ready.then(()=>{
  const k=sodium.from_base64(process.argv[2],sodium.base64_variants.ORIGINAL);
  const s=sodium.from_string(fs.readFileSync(process.argv[3],'utf8'));
  process.stdout.write(sodium.to_base64(sodium.crypto_box_seal(s,k),sodium.base64_variants.ORIGINAL));
});" <公钥> <明文文件>
```

**密钥名不能以 `GITHUB_` 开头**（GitHub 保留前缀），会返回 422。
本项目用的是 `RADAR_TOKEN` 和 `SCAN_TOKEN`。

### git push 走不通的原因

网络环境里 git over HTTPS 会先撞 HTTP/2 framing 错误（加 `http.version HTTP/1.1` 可解），
再撞代理 CONNECT 502（用户终端无代理变量），最后撞 git 认证对细粒度 token 的限制。
**改用 REST API 上传（`upload_via_api.py`）完全绕开，19 个文件全部成功。**

### 手动触发 workflow

`POST /actions/workflows/radar.yml/dispatches` 需要 `Actions: write`，
本 token 缺这项（细粒度 token 的 Actions 权限与 workflow_dispatch 端点不完全匹配）。
**不影响挂机**——cron 定时触发不需要这个权限。
需要手动触发时，直接在网页点 Actions → Run workflow 即可。
