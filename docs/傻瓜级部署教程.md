# 傻瓜级部署教程（从零到挂机，全程约 40 分钟）

> 全程只需复制粘贴。**不需要你会写代码**，每条命令都给了完整内容。
> 花费：0 元（公开仓库的 GitHub Actions 免费）。
>
> ⚠️ 先看这一条：**做完不等于有钱**。本系统能把"钱在哪、怎么拿"这件事查清楚并自动化，
> 但收入取决于你投入的时间与选题质量。实测数据参考：同类 AI 代理 30 天毛收益 $500–800
> （社区公开实验），且收益高度集中、波动大。请当副业，不要当收入替代。

## 第 1 步：确认你的 GitHub 账号能写（2 分钟）

打开终端（Mac 上是"终端"App，Windows 上用 PowerShell），粘贴：

```bash
curl -s https://api.github.com/user | head -5
```

**如果看到 `"login": "你的用户名"`** → 说明你的网络能访问 GitHub，继续第 2 步。

**如果看到报错** → 说明国内网络需要配代理。设置后重试：

```bash
# macOS / Linux
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
# 把 7890 换成你自己代理软件的端口
```

---

## 第 2 步：建仓库（3 分钟）

**方式 A（推荐，最简单）**：浏览器打开 <https://github.com/new>

- Repository name 填：`bounty-radar`
- 选 **Public**（公开仓库的 Actions 免费，私有仓库只有 2000 分钟/月额度）
- **不要**勾选 Add a README（我们要本地传文件）
- 点 Create repository

**方式 B（命令行）**：先在 GitHub 网页生成一个 Personal Access Token：
<https://github.com/settings/tokens/new> → Note 填 `radar` → Expiration 选 90 days →
勾选 `repo` 和 `workflow` → Generate token → 复制那串 `ghp_...`（**只显示一次，存好**）。

然后：

```bash
git config --global user.name "你的用户名"
git config --global user.email "你的邮箱"
```

---

## 第 3 步：把代码推上去（3 分钟）

在终端粘贴（先把下面两行的 `你的用户名` 和 `你的TOKEN` 换掉）：

```bash
cd ~
git clone https://github.com/你的用户名/bounty-radar.git
cd bounty-radar
```

然后把本项目文件夹里的 `radar/`、`store/`、`.github/` 三个目录复制进这个目录。
（最简单：直接用 Finder 拖进去）

再执行：

```bash
git add -A
git commit -m "init: bounty radar"
git push
```

> 如果提示要输密码：**Personal Access Token 就是密码**，粘贴那串 `ghp_...`（终端里粘贴密码不显示字符，是正常的）。

---

## 第 4 步：开启挂机（1 分钟）

浏览器打开你的仓库 → 点 **Actions** 标签 → 左侧选 **挂机收益雷达** →
点右侧 **Run workflow** → 等 2 分钟。

**成功标志**：Actions 里出现绿色对勾，点进去能看到 4 个步骤全绿，
最后一步显示"已创建提醒 Issue"（或"本轮无达标目标"）。

**为什么这就叫挂机了**：
`radar.yml` 里写的是 `cron: '0 3,9,15,21 * * *'`，也就是**每 3 小时自动跑一次**，
GitHub 的服务器替你跑，你的电脑可以关机。它会把新发现的高价值赏金写成报告提交到仓库，
并自动开一个 Issue 提醒你。

---

## 第 5 步：本地验证扫描器（可选，2 分钟）

想在本地看结果（不依赖 GitHub Actions）：

```bash
cd ~/bounty-radar
python3 radar/scan.py
```

打开 `reports/latest.md` 看报告。

**如果报 "API rate limit exceeded"** —— 这是未登录调 GitHub API 的正常限流（每 IP 60 次/小时）。
解决办法二选一：
- 等一小时自动恢复
- 或配置 token（限流提到 5000 次/小时）：

```bash
export GITHUB_TOKEN=你的ghp_token
python3 radar/scan.py
```

## 第 6 步：看懂报告，知道哪些能赚钱（重要）

打开 `reports/latest.md`，重点看两个字段：

### 字段 1：`自动适配度`

| 值 | 含义 | 能不能无人挂机 |
|---|---|---|
| **极优** | 标注 15 分钟内可完成 | ✅ 单次运行就能做完，最适合 |
| **优** | 标注 1 小时内 | ✅ 适合 |
| 中 | 数小时～1 天 | ⚠️ 需要更多轮次 |
| 待判 | 无工时标注 | ❓ 人工看 |

### 字段 2：`大陆可收款`

| 值 | 含义 |
|---|---|
| ✅ 是 | 通道可行（Creem/Paddle/PayPal 类自建产品） |
| ⛔ 否 | **钱到不了你账上**，别浪费时间 |
| ❓ 需确认 | 需要自己核实 |

> 现实中被扫出来的高额赏金**绝大多数是 ⛔**——因为主流赏金平台走 Stripe。
> 这不是雷达出错，而是真实情况。所以下一步走第 7 步（自建产品），而不是硬啃赏金。

## 第 7 步：启动真正的创收链路（自建数字产品）

### 7.1 先拿到产品选题

```bash
cd ~/bounty-radar
python3 store/publish.py --limit 8 --price 2900
```

它会从需求信号里提炼选题、生成产品定义到 `store/products/`。
输出示例：

```
从需求信号中提炼 3 个选题：
  · [Feature] HR页应该也能批量创建任务
    来源：pt-plugins/PT-depiler
已生成 3 个产品定义到 store/products/
=== 演练模式（未真实上架）===
  [产品] [Feature] HR页应该也能批量创建任务
          定价 $29.00 | slug=feature-hr
```

**此时没有上架任何东西**，只是本地生成定义。先手动改内容——自动生成的只是骨架，
你需要把产品描述改成真正解决那个 issue 的方案。`store/products/*.json` 直接编辑即可。

### 7.2 开通 Creem 收款（关键步骤，见 docs/收款通道可行性.md 的清单）

1. 注册 <https://www.creem.io>（**支持中国大陆个人**）
2. 按 `docs/收款通道可行性.md` 末尾的清单准备好：域名、落地页、隐私政策、退款规则、条款、客服邮箱
3. 创建产品，把 7.1 里的 name / description / 价格填进去
4. 提现方式选 **Alipay（支付宝）**，受益人姓名必须和验证信息完全一致
5. 上架后拿到 Checkout 链接

> **为什么是 Creem 而不是 Algora/Polar**：那两个走 Stripe，大陆个人开不了户，
> 就算赏金付了钱也提不出来。Creem 是 MoR 平台（平台代缴全球销售税），
> 支持大陆个人提现到支付宝，费率 3.9% + $0.40。

### 7.3 让创收链路也自动跑

在 `.github/workflows/` 下新建 `store.yml`：

```yaml
name: 数字产品自动上架
on:
  schedule:
    - cron: '0 4 * * *'   # 每天 UTC 04:00 = 北京 12:00
  workflow_dispatch:
permissions:
  contents: write
  issues: write
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: 生成产品定义
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          python3 radar/scan.py
          python3 store/publish.py --limit 8 --price 2900
      - name: 提交产品定义
        run: |
          git config user.name  "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add store/ reports/
          git diff --staged --quiet || git commit -m "chore: 更新产品定义 $(date -u +%F)"
          git push
      - name: 真实上架（需配置密钥）
        if: ${{ secrets.CREEM_API_KEY != '' }}
        env:
          CREEM_API_KEY: ${{ secrets.CREEM_API_KEY }}
        run: python3 store/publish.py --limit 8 --price 2900 --publish
```

**配置密钥**：仓库 → Settings → Secrets and variables → Actions → New repository secret →
Name 填 `CREEM_API_KEY`，Value 粘贴 Creem 后台的 API Key。

配好后，这条工作流每天自动跑：扫描需求 → 生成产品定义 → 提交 → 上架。

## 第 8 步：可选 —— 让 AI 帮你写代码并提 PR（进阶）

这一步是"抢赏金"链路。**先读清楚再决定要不要做**：

### 现实预期（实测数据）

| 维度 | 实际情况 |
|---|---|
| 30 天毛收益 | $500–800（社区公开实验，59/84 PR 被合并） |
| 收益分布 | 极度集中，3 个仓库占 90%+ |
| 纯自动化提 PR | **会被判为机器人、毁掉账号信誉** |
| 有效模式 | 人在环中（AI 做 90%，人审核后提交） |
| 收款 | ⛔ 主流平台走 Stripe，大陆个人提不出来 |

### 如果还是要试（务必按这个顺序）

```bash
# 1) 先看有什么可做，不做任何写操作
python3 radar/hunter.py --scan --limit 10

# 2) 认领一个（会生成评论到 outbox/，先看再发）
python3 radar/hunter.py --claim --repo owner/repo --issue 123

# 3) 手动确认评论内容 OK 后，才加 --yes 真的发出去
python3 radar/hunter.py --claim --repo owner/repo --issue 123 --yes

# 4) 克隆仓库、读 CONTRIBUTING、探测测试命令
python3 radar/hunter.py --solve --repo owner/repo --issue 123

# 5) 把补丁放好后应用（补丁需要由 AI/人工生成）
python3 radar/hunter.py --solve --repo owner/repo --issue 123 --patch-file /path/to/fix.patch
```

**认领时的关键**：一定要写清具体方案，别只写"我来试试"。
维护者接受外部 PR 的决定性因素是**你表现出的领域深度**，不是代码量。

## 常见问题

**Q：Actions 报错 `Resource not accessible by integration`？**
A：仓库权限设置问题。仓库 → Settings → Actions → General → Workflow permissions → 选
"Read and write permissions"。或直接改用 `secrets.GITHUB_TOKEN` 传参（`radar.yml` 已这样写）。

**Q：报告里全是"⛔ 大陆不可收款"，是不是没用了？**
A：这正是真实情况。它的价值在于**提前告诉你别浪费时间**，同时把可做的自建产品选题指出来。
路径 A（第 7 步）才是给你真正能收到钱的路。

**Q：会不会是诈骗？**
A：雷达已内置反作弊。实测中拦下了三个"挂着 $660/$750/$3000 标签但从未付过款"的仓库，
判据是：真人合并 PR 数 = 0、贡献者 = 1、关注者 = 0、fork/star 比异常。
详见 `radar/scan.py` 的 `farm_signals()`。

**Q：真的能"完全不用管"吗？**
A：扫描、报告、Issue 提醒、产品定义生成、上架都已自动化。但**内容质量需要人工把关**——
自动生成的商品描述只是骨架，直接上架大概率卖不动。合理分工是：机器跑流水线，你做选题和文案。

**Q：多久能看到钱？**
A：诚实回答：不确定，且可能很久。挂机系统解决的是"信息与流程"，不解决"需求与信任"。
建议先用路径 A 验证第一笔（哪怕 $9），再决定是否放大。
